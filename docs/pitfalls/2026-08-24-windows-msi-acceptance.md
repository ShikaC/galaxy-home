# Windows MSI 验收收口踩坑

## Medium 令牌不会继承另开的管理员 PowerShell

### 发现

用户已打开管理员 PowerShell，但 Codex 桌面进程仍为 Medium 完整性级别；从该进程直接运行 `perMachine` MSI 仍会返回 1925/1603。

### 根因

Windows 提升只作用于被 UAC 授权的新进程，不会反向提升已经运行的 Codex 会话。管理员组成员身份也不等于当前令牌已经提升。

### 处理

由当前会话调用 `Start-Process -Verb RunAs` 启动 `msiexec`，用户在 UAC 安全界面人工确认；随后通过 MSI 日志、注册表和文件系统判断完成状态，不尝试自动操作安全提示。

### 下次避免

验收前分别记录组成员、`IsAdmin` 和完整性级别。对于 `perMachine` MSI，把“用户有管理员账户”和“当前安装进程已提升”视为两个独立条件。

## 大量小文件使 MSI 安装和卸载耗时较长

### 发现

安装副本包含约 1.8 万个文件。安装和卸载期间，客户端 `msiexec` 长时间存在，短轮询容易误判为卡死。

### 根因

生产 Node 依赖包含大量小文件，Windows Installer 需要逐个注册、复制、注销和删除组件；过程日志可达到数十 MB。

### 处理

同时观察 MSI 日志长度、最后写入时间、当前动作、产品注册和安装目录。只有日志停止前进或出现最终错误码时才判定失败；成功必须以状态 `0` 和 `MainEngineThread is returning 0` 为准。

### 下次避免

为 MSI 安装/卸载预留数分钟，不用固定的短超时判断失败。先看日志是否持续增长，再决定是否需要诊断卡死。

## WebView 文件输入会打开系统公共文件对话框

### 发现

点击“恢复数据”后，文件对话框显示在银河居所窗口之上，但 Computer Use 的坐标点击会因 WebView 子进程与壳进程边界而拒绝。

### 根因

Tauri 页面由 WebView2 子进程渲染，系统公共文件对话框又由壳拥有；截图能同时看到两者，但坐标命中的前台进程不一定等于选定的壳窗口。

### 处理

保留银河居所为唯一目标窗口，使用文件对话框已经聚焦的“文件名”字段输入精确本地路径，再用 `Return` 提交；出现应用内二次确认后，根据用户刚给出的恢复确认点击“确定”。

### 下次避免

不要绕过 Computer Use 的跨进程输入拒绝，也不要用 PowerShell UI Automation。遇到公共文件对话框时优先使用标准键盘导航，并在每次输入后重新观察界面。
