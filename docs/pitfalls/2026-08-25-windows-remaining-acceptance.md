# Windows 剩余桌面验收踩坑

## Computer Use 启动安装器可能触发应用容器虚拟化

### 踩坑

通过 Computer Use 直接启动 NSIS 后，界面显示安装成功，但实际文件落在 Codex 应用容器的 LocalCache 虚拟路径，桌面快捷方式指向的正常安装目录并不存在。

### 根因

Codex 桌面应用处于打包应用上下文。由该上下文直接启动安装器时，Windows 可能对用户目录和快捷方式写入做文件虚拟化；安装 UI 的“成功”不等于目标用户环境真实安装成功。

### 解决

先将虚拟化安装完整卸载，再用 PowerShell `Start-Process -Verb RunAs` 启动同一 NSIS，由用户人工确认 UAC。安装后同时验证正常安装目录、卸载器、快捷方式目标、资源路径、进程和端口。

### 下次避免

桌面安装验收不能只看安装向导。必须解析快捷方式目标并确认目标存在，同时检查实际进程可执行路径；安全桌面提示只由用户操作。

## `GetDpiForSystem` 可能返回调用进程虚拟化后的 DPI

### 踩坑

Codex 进程调用 `GetDpiForSystem()` 得到 96 DPI，看似为 100%，但 Windows 设置页显示主显示器实际为 125%。

### 根因

返回值受调用进程 DPI awareness 与系统虚拟化影响，不能单独作为显示缩放验收依据。

### 解决

以 Windows 设置页为系统缩放证据，并用实际 WebView/Playwright 的 `deviceScaleFactor` 和输出像素尺寸交叉验证。150% 测试结束后恢复原始 125%。

### 下次避免

记录缩放时至少保留两个独立证据：设置页当前值和应用渲染像素比。不要从普通宿主进程的单个 Win32 返回值推断真实缩放。

## Computer Use JPEG 重采样不适合判断字体缺陷

### 踩坑

150% 原生截图中的细笔画看似破损，容易误判为缺字或字体渲染问题。

### 根因

Computer Use 返回 JPEG，并可能做尺寸重采样；压缩块和色度采样会破坏 CJK 细笔画。

### 解决

原生截图用于证明真实窗口和系统设置，视觉细节用新鲜的 1.5 DPR PNG、DOM 几何断言和独立视觉审查确认。

### 下次避免

JPEG 只用于场景证据，不用于像素级缺陷裁决。CJK 断行、方框字和裁切应使用无损 PNG 与元素边界数据。

## 目录存在不代表 Tauri app data 可写

### 踩坑

对已有 app data 目录设置拒绝写入后，`create_dir_all` 仍成功，直到 Node 打开 SQLite 时才失败，原生壳只能显示泛化的子进程退出信息。

### 根因

创建目录只验证路径存在或可创建，不验证当前用户能在已有目录中创建文件。

### 解决

启动 Node 前在 app data 中创建唯一零字节探针并立即删除；失败时显示包含目录不可写原因的原生启动错误。测试结束后精确恢复原 SDDL。

### 下次避免

任何依赖持久化目录的桌面壳都应在启动子服务前做真实写入探针。ACL 测试必须先保存原始 SDDL，恢复后再执行一次写入和正常冷启动。

## Windows 通知拒绝必须同时看系统事件和应用降级

### 踩坑

仅观察不到 toast 无法区分通知未触发、系统拒绝、焦点抑制或测试时机错误。

### 根因

系统通知和应用内提醒是两条独立通道，Windows 还会根据每应用策略记录禁用原因。

### 解决

允许时核对 PushNotification Platform 送达事件；拒绝时核对 `ToastSettingDisabled`，同时实际操作应用内横幅和“30 分钟后”。隐私设置由用户手动切换，结束后恢复。

### 下次避免

通知验收至少保留系统事件、应用内 UI 和设置状态三个证据，不能以“没看到 toast”直接判失败。

## Windows Playwright 不支持 POSIX 行内环境变量语法

### 踩坑

`PORT=... command` 形式的 `webServer.command` 在 Windows 上无法启动；两套测试并行时固定端口还会互相占用。

### 根因

Windows npm shell 不解释 POSIX 行内赋值，且固定端口把独立测试进程耦合到同一全局资源。

### 解决

通过 Playwright 的结构化 `webServer.env` 传值，并由 npm 入口在每次运行开始时一次性分配独立的临时端口组。

### 下次避免

跨平台测试命令不要依赖 shell 环境赋值语法。需要并发的 E2E 必须把端口视为测试实例资源，而不是仓库常量。

## Modern Standby 可能非常短

### 踩坑

睡眠监控的最大采样间隔只有约 5 秒，单看 CSV 容易认为主机没有真正进入睡眠。

### 根因

支持 Modern Standby 的主机会因输入或平台策略很快恢复，应用采样间隔不能证明电源状态转换。

### 解决

用 Kernel-Power 506/507 事件证明进入和退出 Modern Standby，再用唤醒后的应用、Node、监听端口和真实搜索操作证明恢复能力。

### 下次避免

睡眠验收把系统电源事件作为状态证据，把应用监控作为连续性证据；两者缺一不可。

## 递归清理证据被策略拒绝时不要绕过

### 踩坑

本轮尝试清理 `.tmp` 中便携 Node 与基线副本时，递归删除被执行策略阻止。

### 根因

大范围递归删除容易误删用户证据或工作区数据，策略要求明确且可验证的目标边界。

### 解决

停止绕过，保留整个未跟踪验收证据目录，不纳入提交；只删除可通过补丁精确定位且不再需要的调试 journal。

### 下次避免

验收开始时将可丢弃工具、持久证据和数据基线分到不同临时目录。结束时逐一验证绝对目标，再执行最小范围、可恢复的清理。
