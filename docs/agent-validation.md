## 检查了哪些失败

- 格式错误、超出日期或时间预算、未知来源、重复任务：拒绝提案，格式或约束错误最多修正一次。
- 确认前修改或归档笔记、变更引用任务或撤销权限：拒绝使用旧依据执行。
- 事务中途写入失败：本次任务和日期关联全部回滚，可以安全重试。
- 重复提交、双连接并发、确认与取消交错：读取锁内权威状态，避免重复创建或覆盖终态。
- 生成超过最初租期：心跳续租；过期或遗留记录恢复为明确中断状态，迟到响应不能覆盖取消或恢复结果。
- 备份中的运行 JSON 损坏或内外标识不一致：恢复前拒绝，已有工作空间保持完整。
- 新建笔记请求尚未完成时快速编辑：暂时禁用旧编辑器，避免将输入写到旧笔记并触发错误的离开保护。
- 同一本地日期切换时区：每日提醒按日期和类型复用，已关闭的晨间提醒不会因为 UTC 时间变化而再次出现；下一天仍正常生成。

评测检查器自身也有反例测试：意外修改设置或未来新增表、遗漏一个执行结果、重复结果、错误标题／分钟／日期都会使检查失败。确认前快照只允许运行记录变化；重复确认后的快照包括全部表。

## 检索对照与限制

固定合成语料的 Recall@6：最近六篇基线为 **6／30（20%）**，词项与汉字二元片段排序为 **25／30（83.3%）**；排序方法 MRR 为 **0.833**。五个没有共同词项的同义表达仍然漏检，说明当前方法的语义局限。这些数值只适用于仓库中的合成语料。

Fixture 的 90／90 表示固定模型输出下工作流与状态检查通过，不能写成“Agent 真实任务成功率 100%”。本轮真实调用仅提供小样本硬性检查与延迟、token 数据，不能代表总体任务质量。用户采纳率、节省时间和长期完成率仍未测量；价格不确定时保留 `null`，不推算费用。
