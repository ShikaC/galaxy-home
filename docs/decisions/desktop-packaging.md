## 需求对照

| 诉求 | 浏览器现状 | 缺口 |
|------|------------|------|
| 本机单用户工作区 | `127.0.0.1` + SQLite | 无系统托盘/开机自启 |
| 提醒 | 进程内横幅 + 错过补显 | 关闭浏览器后无系统通知 |
| 分发 | `npm start` / 开发服 | 无安装包、无应用图标 |
| 手机 | ≥768 防溢出 | 无专门手机布局 |

## 方案比较

| 方案 | 收益 | 成本 / 风险 | 与本地 SQLite |
|------|------|-------------|----------------|
| **继续浏览器** | 零额外壳；现有 CI/e2e 不变 | 无后台通知；启动路径偏开发者 | 已满足 |
| **Tauri 轻壳**（已选） | 小体积；可接系统通知；仍用本地 Node/Rust sidecar 或内嵌静态 + 现有 API | 需打包 Node 服务或迁 Rust/sidecar；签名与自动更新 | 适合：壳内起现有 Fastify，数据目录指到用户目录 |
| **Electron** | 生态熟、通知/托盘资料多 | 体积大、内存高；与「轻量书桌」气质冲突 | 可行但偏重 |
| **PWA** | 安装感、离线缓存 | 本地 SQLite + 本机 API 与 Service Worker 模型冲突；离线写库难 | **不优先** |
| **手机专门适配** | 外出补记 | 信息架构需重排；说明书明确延后 | 在桌面壳稳定后再做响应式深化 |

## 通知策略

1. 应用内横幅与错过补显保持不变。
2. **Tauri 第一刀（已落地）**：due 提醒在壳内镜像系统通知（需授权）；不承诺关机后的 OS 调度。
3. 不把通知做成第二套业务状态源；仍以 SQLite `notifications` 为准。
