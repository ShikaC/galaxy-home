# Galaxy · 个人工作空间

新版产品方向是“类滴答清单 + AI 智能集成”：以任务和时间管理为中心，让 AI 参与记录、整理、安排、执行和重排。

`main` 已实现新版任务、重复、多提醒、日 / 周日历及 AI 录入 / 重排代码，已完成首个新版阶段交付：M0–M3 首场景、视觉双复核、重启验证、最终 lint/typecheck/build 与旧版 E2E 50/50 均通过。真实模型 8 次请求已记录；M4/M5 和平台边界仍待验收。项目、知识笔记、习惯、回顾和旧 AI 计划继续保留。服务仅监听本机，尚无账号与跨设备同步。

实施路线是在现有仓库重构任务与时间核心，复用存储、迁移、备份和 AI 执行保障。先完成任务 / 重复 / 提醒与日历容量，再接入 AI 重排、跨端同步和交付体验。阶段细节以新版需求为准。

历史说明书及早期“仅电脑端、无同步、今日主要最多三项”等规定只说明旧版行为，不限制新版产品设计。以下功能和启动说明描述当前实现。

启动支持增量数据库迁移，并在已有库升级前生成独立快照；快照失败或数据库版本高于当前程序支持范围时停止升级。本轮已在两份旧库的再备份副本中核对 v8 → v11 迁移，用户原数据未迁移。回退时先停止应用、恢复升级前数据库副本，再启动对应旧版本。新导出包为 v2，恢复兼容旧 v1 包；密钥不进入业务备份。

新版任务支持单层子任务、优先级、日期截止 / 时间截止、预计耗时和一个连续安排时段。旧多分类关系继续保留；完成父任务前需处理未完成子任务。子任务区的添加/保存立即生效，取消上方父任务编辑只丢弃父草稿。重复规则覆盖日 / 周 / 月及周一至周五工作日，月末不存在的日期跳过；系列模板修改只影响尚未生成的实例，已生成与手动改单次实例保留。重复调度用持久游标分批补齐离线期间实例，单个系列的 DST 时间错误会记录并隔离。

从「日历」查看安排、空闲时间与冲突，从「任务 AI」录入多任务或按剩余时间重排。任务 AI 的新增与重排都需审查确认；保守模式的录入只发送本次原文，读取真实日历进行重排需要在设置启用开放模式，确认时会再次检查权限。固定日程、已完成任务及明确锁定任务受到服务端约束保护。手动流程不依赖模型连接。

多提醒可分别绑定时间截止或安排开始，时间修改后旧待提醒失效；延期请求保存首次绝对提醒时间，重试、重启和恢复后不重复向后延期。当前能力覆盖应用运行期间和恢复后的补显；桌面系统通知的提交、OS 实际显示、完全退出后的后台提醒是不同边界，尚未宣称退出后可靠送达。


## AI 行动计划与工程验证

从侧栏「AI 计划」把目标和相关笔记变成 1–7 天的限时行动。模型只提出建议，服务器检查时间、引用和重复任务；你确认后才执行。执行结果和运行记录保存在本地，支持刷新恢复、重复请求去重、失败回滚、过期资料保护和 JSON 导出。

- `npm run eval -- --repetitions 3`：30 个合成场景的确定性状态评测，同时比较笔记检索方法；不调用外部服务。
- [真实模型体验](docs/live-model-usage.md)：用户配置模型的实际调用、体验问题、产品改进和小样本结果。计划支持生成中取消、直接回答追问、确认前编辑与版本冲突保护。
- [验收记录](docs/agent-validation.md)：可复现的检查命令、通过结果、失败场景与指标边界。
- `npm run eval -- --live --secrets /absolute/path/to/secrets.json --repetitions 3`：使用已配置模型测量合成场景；与固定输出回归分开报告。
- CI 检查 lint、类型、单元/集成测试、生产构建、评测和全部 Playwright 流程，并保留评测及浏览器验证产物。

[架构、状态机、评测方法和五分钟演示](docs/agent-engineering.md)说明了已经实现的能力及尚未测量的边界。真实模型指标和用户收益不使用模拟数据代替。


## 这个版本能做什么

- **每日工作台**：今日计划／收集箱／已完成、项目概览、近期笔记、习惯与 AI 工作入口。所有内容来自实际本地数据。首页可直接输入记录，回车入收集箱；详细录入仍可打开弹窗。
- **知识笔记**：创建、编辑、手动保存、置顶、归档恢复和 Markdown 导出。离开未保存的笔记会提示。笔记纳入全局搜索、AI 开放模式上下文与数据备份。
- **专注计时**：25／50 分钟、开始／暂停／重置和专注模式。倒计时按结束时间计算，切换页面或刷新后仍可恢复；状态保存在当前浏览器的本地存储中，不进入数据库备份。
- **响应式空间**：桌面固定侧栏、平板图标导航、手机顶部导航，AI 可从任意页面展开。首次进入可先手动使用，不插入教学示例。
- **收集箱与待办**：统一条目模型；自定义单层分类；多分类归属；完成 / 归档；今日主位 / 次要 / 重点安排。
- **随手记**：任意页快速记下；可配置语音转写（未配置时文本仍可用）。
- **周期项目**：创建目标与周期；按阶段渐进拆解；项目页推进与反馈；AI 可协助当前阶段（也可纯手动）。
- **习惯**：打卡型与计数型；每日 / 每周频率、休息日；今日完成、超额、撤销与请假修正。
- **回顾**：直接记录每日收获，按日期或关键词检索，再用本地数据或 AI 生成周回顾；建议可转成待办 / 习惯 / 项目。
- **AI 助手（可选）**：规划今日、拆解目标、梳理知识；围绕任务或笔记准备上下文对话；长期记忆与可追溯的实际操作。需要在设置中连接可用的模型服务。快捷入口和笔记工具会先填入草稿，由你发送。
  - **保守模式**：可提议非删除操作，须你确认后执行；不支持删除 / 归档。
  - **开放模式**：多数操作立即执行；**移入回收站仍须确认**；归档立即生效。
  - 未配置或服务不可用时，其余功能照常使用。
- **搜索、回收站、操作记录**：全局搜索，命中待办可直接打开详情（`?item=` 深链）；软删除进回收站可恢复；AI 自动操作可查看与撤销。
- **提醒**：应用运行期间通知；桌面壳可将 due 提醒镜像为系统通知；关闭后错过的提醒会在下次启动补显。
- **桌面壳（可选）**：Tauri 包装本机 Web + API；数据目录默认在用户 Application Support。
- **设置与数据**：工作区命名、时区、AI 权限与密钥（存本机 `secrets.json`）；手动导出 / 恢复业务数据（**密钥不进入导出包**）；本地自动备份。

## 要求

- Node.js **≥ 24**
- 本机浏览器访问（默认不暴露到局域网）
- 桌面壳另需：**Rust stable**（`rustup`）与本机 Node（暂不内嵌）

## 启动

```bash
npm install
npm run dev
```

开发地址：<http://127.0.0.1:5173>（API 默认 `:3001`）。

生产（浏览器）：

```bash
npm run build
npm start
```

生产地址：<http://127.0.0.1:4173>。

桌面壳（Tauri）：

```bash
npm run desktop          # 开发：窗口 + Vite/API（默认 Web :5180 / API :3010，可与浏览器 :5173 并行）
npm run desktop:build    # 打包：构建前端/服务资源后产出安装包
```

桌面生产窗口加载本机服务（优先 `http://127.0.0.1:4177`，端口占用时自动顺延至 `4199`），由壳进程拉起 Node。

### AI 连接

在「设置 → AI 服务」填写 OpenAI Chat Completions 兼容服务的地址、模型和密钥，保存后测试连接。地址可填写服务根域名（自动使用 `/v1`），也可填写服务商提供的 API 基础路径，例如 `/v1` 或 `/openai/v1`；不要填写网站控制台页面。

AI 请求优先使用 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 环境变量（小写变量优先）。未设置 HTTP/HTTPS 代理变量时，macOS 会读取已启用的系统 HTTP/HTTPS 代理；本机模型地址始终直连。代理在首次 AI 请求时读取，修改代理设置后请重启应用。仅配置 PAC 或 SOCKS 的环境需另外提供 HTTP/HTTPS 代理地址。

## 数据目录

重启不会清空数据。浏览器开发和桌面壳默认落在**两套不同的目录**，看起来像丢数据，其实是连到了另一份库。两端都可以用环境变量 `GALAXY_DATA_DIR` 指向同一目录。

| 怎么启动 | 默认数据目录 |
|------|------|
| `npm run dev`（浏览器） | 项目下的 `./data/` |
| `npm run desktop`（桌面壳） | macOS：`~/Library/Application Support/app.galaxyhome.desktop`；Windows：`%APPDATA%\app.galaxyhome.desktop` |

设置 → 数据与回收站会显示当前进程正在使用的绝对路径，可复制。

| 路径 | 内容 |
|------|------|
| `galaxy-home.sqlite` | 业务数据库 |
| `secrets.json` | AI / 转写密钥（不进入导出包） |
| `backups/` | 自动备份 |
